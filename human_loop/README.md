# human_loop —— 人工干预/人工核验专区（2026-09-12 建）

> 这里放**需要人来判断**的事务：标注一致性检验（Cohen's κ）、疑似脏标注类的人工核验、类别合并清单的人工评审等。
> 纪律：**只读 train/val 数据集**；产物只写本目录 `exports/`（不入 git）；不参与训练、不改数据集。

## 一、为什么需要它
混淆矩阵可以筛选值得人工复核的易混淆类对，但不能单独证明“任务内在歧义”或“模型已达到人类上限”。本工具在与训练完全一致的252类标签映射下生成两轮独立盲标包，并报告Cohen's κ、人工准确率与模型同批表现；结论必须等新实验完成后再根据数据给出。

> **口径警告：** 旧254类抽样包包含“插头电线/充电线”和“蔬菜/菜根菜叶”，而这两对在252类协议中已分别合并成同一输出类。2026-09-29首次252类A轮又使用了未显示公共类成员的协议v2界面。两类旧包及其首轮结果均只作历史保留，不得继续配对出正式报告。当前协议v3固定显示公共合并类成员，GUI和报告会拒绝旧协议包。

## 二、文件与用法

| 文件 | 作用 |
|---|---|
| `hl_common.py` | 共用工具：252类映射、短名解析、合并成员拦截、公开包完整性校验、**Cohen's κ 计算**、κ 分级 |
| `make_kappa_pack.py` | 生成**盲标抽样包**：易混淆类对平衡抽样 → 打乱文件名 → 两张空白标注表 + 答案键 |
| **`annotate_gui.py`** | **图形标注界面（推荐用这个标注）**：看图 → 二选一 → 自动存盘；绝不读答案键，保证盲标 |
| `kappa_report.py` | 严格校验协议/答案键/标注表/图片集合 → 逐类对 **p_o / p_e / κ** + 宏平均κ + 两轮准确率 +（可选）**模型同批准确率** → CSV + Markdown |
| `selftest_human_loop.py` | 71 项自动化自检（改代码后跑，日常不用） |
| `_probe_gui_states.py` | **一次性诊断脚本**（不入 git）：复现"选完返回上一题配色异常"，逐步打印两颗选项按钮在不同状态下的生效配色并核对不变量 |

### 1) 生成抽样包
```bash
D:\Python\Python3.10.7\python.exe src_v2\human_loop\make_kappa_pack.py
# 默认：内置 8 组易混淆对 × 每类 15 张 = 240 张（val 集）
# 自定义：--pairs "锅:电饭煲,盒子:纸箱"  --n-per-class 20  --seed 20260912
# 重做实验时排除旧包已看过的图片：--exclude-pack <旧包目录>
```
产物 `exports/<时间戳>_kappa_pack/`：
```
images/P01/P01_001.jpg ...    图片副本（文件名不含类别线索，保证盲标）
pairs.csv                     类对清单
sheetA.csv / sheetB.csv       两张空白标注表（option_1/2 为两个候选类，**类对内左右顺序固定**，见 §2.1）
_key.csv                      ⚠ 答案键（标注者不得打开）
protocol.json                 盲标协议、252类定义哈希、完整映射哈希、研究设计、随机种子与类对清单
public_manifest.json          公开完整性清单：图片内容SHA256、类对表哈希、两轮标注表不可变字段哈希
README_ANNOTATOR.txt          标注者须知
```

### 2.1 选项顺序策略（2026-09-12 按使用反馈修订）
- **旧行为**：每张图的左右候选顺序独立随机（`make_kappa_pack.py --per-image-order`）→ 标注时要反复重读左右标签、容易点错且无从判断自己是否点错。
- **现行为（默认）**：**类对内固定、类对间随机且整体平衡**——同一 `pair_id` 的所有图片共用同一左右顺序；8个默认类对按种子打乱后固定为4组A类在左、4组B类在左。
- 抽样器还会对整包源图路径全局去重；若共享类别导致剩余图片不足，或任一类不足指定张数，会直接失败，不会静默缩减240张预注册样本量。生成时同时记录源图与复制图SHA256；GUI会在标注前校验公开清单、CSV不可变字段和全部图片内容，报告阶段再核验答案键、源路径目录语义和源图哈希。
- 改答方式：按 `←` 回到该题，重新点另一个选项**直接覆盖**（界面会提示"↻ 已改答：…（原：选项 1）"）；也可 `Delete` 清除本题、4 秒内 `Ctrl+Z` 撤销清除。CSV 每次作答即原子写盘，无需手工改表。
- 旧254类抽样包不能通过调整候选顺序修复；必须在当前252类协议下重新生成。

### 2) 人工标注（关键规矩）
**推荐：用图形界面标注（不用手工找图）**
```bash
D:\Python\Python3.10.7\python.exe src_v2\human_loop\annotate_gui.py
# 当前协议v3新包，第一轮A（公共类成员提示固定显示）：
D:\Python\Python3.10.7\python.exe src_v2\human_loop\annotate_gui.py --pack 20260929_141055_kappa_pack --annotator A
# 为降低刚完成旧A造成的短时记忆，建议不早于 2026-09-30 00:41:47 +08:00 开始本轮A。
# 间隔至少12小时后再做第二轮B；第二轮前不要查看sheetA：
D:\Python\Python3.10.7\python.exe src_v2\human_loop\annotate_gui.py --pack 20260929_141055_kappa_pack --annotator B
# 界面自检（自动构建+模拟作答，不产生真实标注）：
D:\Python\Python3.10.7\python.exe src_v2\human_loop\annotate_gui.py --ui-selftest --annotator UITEST
# 说明：自检强制标注者为 UITEST（绝不写真实 sheetA/B），并针对"当前题序 app.idx"那一行写入校验
# （会话从第一道未答题续标，所以有作答的表里写入行不是第 1 行，自检会打印"写入行=#k"）。
# 自检使用独立sheetUITEST.csv；即使中途异常也会自动清理，不会污染正式A/B表。
```
界面流程：启动页选**抽样包**+**标注轮次（A/B）** → 左侧看图、右侧点两个候选类之一 →
**每次作答立即原子写盘**（`sheet<A|B>.csv`），支持"无法判断(0)"、上一张/下一张、清除本题、备注。
重新打开未完成轮次时，界面会定位第一道未答题；每次补答后继续跳到下一道未答题。右上角同时显示已答和未答数量，只有合法的`0/1/2`才计入进度。
公共合并类会在候选按钮内显示其原始子类参考，内容直接来自`taxonomy.py`的`merged_dict`。例如“玻璃制品类”显示“玻璃器皿、玻璃瓶、玻璃壶、玻璃制品”；私有类不显示此行。该参考只解释类别定义，不读取或泄露图片真值。
图片下方常驻显示**本题当前答案**（"本题已选：① 锅" / "本题未作答"），旁边提示"选错了：按 ← 回到该题，重新点另一个选项即可覆盖"，因此不会出现"选了但不确定选的是哪个"的情况。
快捷键：`1`/`2` 选择、`0` 无法判断、`X` 图外·异常标记、`←`/`→` 翻页、`Delete` 清除本题（4 秒内 `Ctrl+Z` 撤销）、
`Ctrl+S` 保存、`Ctrl+Q`/`Esc` 保存退出。**备注框获焦时按键一律放行给输入框**（不会抢键丢备注）；
已声明 DPI 感知，125% 系统缩放下不再发糊。
（GUI **只读图片**、**绝不读 `_key.csv`**，因此不会泄露答案；标注者看不到文件名与真实类别。）

> **轮次条件必须一致：** 当前协议v3把“显示公共合并类成员”绑定为固定界面条件，A/B两轮不得关闭或改变。旧协议v2的A轮已原地保留为历史结果；正式结论只能使用新协议v3包中重新完成的A/B。

**选项按钮配色语义（2026-09-12 二次整改，解决"返回上一题后选中色看着不对"）**：

| 状态 | 外观 | 说明 |
|---|---|---|
| 未选 | 极淡底（①淡蓝 / ②淡紫）+ 同色相描边 + 深色字 | 选项①恒为蓝、选项②恒为紫，跨题跨状态保持身份色 |
| 悬停 | 同色相**再深一档的淡色**（永不用实心彩色） | 悬停绝不能被误读成"已选" |
| 已选 | **实心彩色 + 白字 + 绿描边 + `✓` 前缀** | 永远比悬停醒目；另在图片下方回显"本题已选：① …" |

原因（值得记住）：Tk 经典 `Button` 在**指针停留其内**时进入 `active` 态并绘制 `activebackground`，
而该状态**在键盘翻页后不会自动复位**（只有真正的 `<Leave>` 才复位）。原配色是"未选 = 实心深色、
已选 = 淡色 tint"，恰好倒挂 → 指针压在按钮上时，那颗**没被选中**的按钮画的是更深一档的实心色，
返回上一题就会看到"深色那颗像已选、淡色那颗像没选"。另外原代码未设 `highlightcolor`，
按钮一旦获得焦点描边会变成 `SystemWindowFrame`（深灰）盖掉绿圈。
现方案把 `highlightcolor` 与 `highlightbackground` 设成同色，并在 `<Enter>`/`<Leave>` 时按当前作答
重刷配色（`_hl()`），从根上消除"状态残留导致配色串味"。
配色已按 WCAG 校核：实心底白字 4.55/5.70:1，未选深字 12.9:1，描边对卡片 3.41/3.91:1，
"无法判断"绿字/警告色 5.38/5.00:1（全部达标）。

自检现在会连带验证**30 项配色不变量**（未答/已选1/已选2/无法判断四态 × 描边一致性、悬停色非实心、
已选比悬停醒目、✓ 前缀与真实作答一致），并验证"最后一题作答后原地重绘与回显"与"「图外」标记写入/落盘/取消"。

### 2.2 「图外·异常」标记（2026-09-12 二次整改新增）
- 用途：某张图的**两个候选类都不属于**（或图片本身有问题）时，按 `X` 或点界面上的「图外·异常」按钮，
  往该行 `notes` 写入固定标记词 `[图外]`；再按一次取消。**不动 `choice`、不改表结构、不增加选项数**
  （κ 的"固定二选一"前提因此不受影响）。
- 为什么需要：`choice=0` 只表示“无法判断”，与“两个候选都不属于”是不同事件。把两者分开记录，才能在新实验中分别统计弃权率和图外率。
- 统计用法：`notes` 含 `[图外]` 的行可单独计数（如 `python -c "..."` 或后续脚本），
  `kappa_report.py` 会单独统计该标记，并把任一轮标为图外的样本排除出κ和准确率；它不会被合并成普通错误或“无法判断”。

### 2.3 两轮盲标（252类协议，intra-annotator test–retest）
- 新批次240张由**同一名标注者间隔足够长时间做两轮独立盲标**（第一轮=A，第二轮=B 表），
  论文口径为"自一致性（test–retest）"，**不是**跨标注者一致性——跨标注者 κ 列入后续工作。
- 操作要求：第二轮前**不要打开 sheetA.csv**、不看模型预测、不与人讨论；建议间隔 ≥12 小时、并放慢节奏。
- 完成后跑 `kappa_report.py --pack exports/<新包名> --with-model <252类协议v2模型>`：κ 列只有两轮都有效作答的图像参与计算；脚本会校验 `protocol.json`。

**备选：Excel 手工填表**（不推荐，需要自己按 `images/<pair_id>/` 一张张找图）：
- 同一标注者第一轮填写 `sheetA.csv`，间隔至少12小时后第二轮填写 `sheetB.csv`；第二轮前不得查看第一轮答案；
- 每张图**二选一**：`choice` 填 1 或 2（实在无法判断填 0 并在 notes 说明）；
- 不要打开 `_key.csv`；不要看模型预测；
- 建议每 20-30 分钟休息一次，避免疲劳造成系统性偏差。

## 三、κ 怎么读（Landis & Koch）
| κ | 一致性 | 论文含义 |
|---|---|---|
| <0.21 | 极弱 | 当前样本与流程下复现性很弱，须联合弃权、图外和样本质量解释 |
| 0.21–0.40 | 一般 | 当前流程下边界稳定性有限，不能单凭κ证明“固有歧义” |
| 0.41–0.60 | 中等 | 边界模糊，归因需谨慎（可写"部分歧义"） |
| 0.61–0.80 | 较好 | 边界基本清晰 → 不宜整体归因于歧义 |
| 0.81–1.00 | 几乎完全一致 | 标签清晰，模型错误应视为可改进项 |

⚠ 注意事项（写进论文时必须交代）：① **平衡抽样**；② **选项数固定为2**；③ 必须盲标并报告A/B间隔；④逐类对κ为主、宏平均为整包摘要、池化κ仅补充；⑤报告 `p_o`、`p_e`、有效样本量、弃权数、图外数；⑥低κ不能单独证明“固有歧义”。
